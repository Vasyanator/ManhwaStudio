# Module: modules/new_project

## Purpose

Python helpers for the Rust launcher "New project" flows. The active production path is Rust UI code that launches these helpers for browser automation and legacy-compatible import/download operations.

## Architecture

`adv_fetch_cli.py` (`AdvancedFetchDaemon`) and `adv_fetch_cloak_cli.py` (`CloakFetchDaemon`) provide the browser-automation logic. They are **no longer launched as separate stdio processes**: the unified AI backend hosts them in-process through `modules/ai_backend/browser/service.py` (`BrowserService`) and serves them over the framed IPC protocol (method `browser.command`). `BrowserService` instantiates the active backend's daemon class, redirects its `_emit` so `progress` events stream as IPC `progress` frames and the single terminal event becomes the IPC response, and calls the unchanged `_handle_command`. The Rust side (`src/launcher/new_project/advanced_download.rs` and `.../batch_processing/executor.rs`) sends each legacy command object as the request header `payload`; it no longer spawns Python. The `--daemon`/`main()` stdin entry point is kept only as a manual debugging fallback. The Selenium helper owns a Selenium driver; the CloakBrowser helper owns a persistent Playwright/CloakBrowser context. Both select the active page, collect image candidates from DOM and shadow DOM, filter explicit site-code resources and bare origin URLs from auto-discovery, download validated image bytes into a temporary folder, and report progress/results back to Rust. Auto-discovery uses typed DOM candidate sources so image-context URLs can keep strange extensionless shapes while obvious page/text/static resources are skipped before download. Selenium and Playwright are imported lazily on first browser use, so an AI-only backend never pays that cost. Version compatibility is checked via the `browser.version` command (was the stdio `ready` event); Rust warns when the downloader version differs from the Studio binary version.

Browser-owned state stays inside the daemon. Advanced downloader image candidates first try a parallel `requests` pass using browser-like headers and a Selenium cookie snapshot, except for `blob:` or other non-http URLs. Candidates that still fail are fetched through Selenium in the active tab, then through a temporary Selenium tab. HTTP(S) candidates are not directly navigated in that tab because some servers trigger browser downloads; browser-scoped candidates such as `blob:` may still use direct tab navigation and canvas readback. The currently successful method is preferred for the next remaining candidates in the same fetch run, but failures re-enter the fallback chain.

The CloakBrowser helper keeps the same protocol but uses Playwright page primitives. Normal fetches avoid long-lived response-body capture while the user is only browsing; they use page-context `fetch(..., credentials="include")`, DOM image canvas readback, a temporary Cloak page, and finally a `requests` fallback with context cookies for HTTP(S) URLs. Deep capture installs an observe-only init script before reloading the active chapter page. The script creates the shared capture state, assigns each canvas a stable WeakMap id, and wraps `URL.createObjectURL`, `OffscreenCanvas.convertToBlob`, and `getContext` (forcing `preserveDrawingBuffer` for WebGL) to capture DRM/descramble images; every wrapper must stay observe-only (call the native function, return its real result, swallow its own errors, install once, and spoof `toString`). It must not replace network/transport APIs such as `fetch`, XHR, or `Worker`. Response-body/CDP capture is enabled only for image-like network responses during the active capture window. Auto-review fetch commands accept an optional `cancel_file`; helpers check it between image candidates and return an `auto_result` for already saved images when cancellation is requested. Auto-review groups are computed before download using the same URL-signature shape as the Rust review window; a group with three failed candidates and no successful decoded image is rejected, and remaining links in that group are skipped.

CloakBrowser also owns a deep capture mode that is not implemented for Selenium. It copies image response bodies from the Playwright context and Chromium CDP network bodies when available, reads plain `<img>` tags straight from the page on every drain (the init-script `scanImages` helper fetches each rendered `img.currentSrc`/`src` once via page-context `fetch(credentials="include", cache="force-cache")`, covering http(s)/`blob:`/`data:` sources and authorized images, and skipping opaque cross-origin responses since the network layer already keeps those — this makes plain `<img>` pages appear in the live count instead of only at stop), polls canvas snapshots through preserved native canvas export APIs, captures `createObjectURL`/`OffscreenCanvas.convertToBlob` images drained from the init-script queue (covers DRM/descramble sites), adds visible canvas screenshots as a per-element compositor fallback, and returns decoded image bytes as the existing `auto_result` payload for Rust auto-review. Stop drains a few extra times (`_settle_deep_image_reads`) so in-flight `<img>` reads from a fast start→stop still land. The `deep_intercept_status` poll reports a live breakdown rather than one number: the `intercept_count` event carries `found_pages` (raw payload total), `found_canvases` (canvas-element captures), and `found_images` (everything else — plain `<img>`, network bytes, blob/descramble exports), classified by `_deep_capture_is_canvas_source`, so the UI can show "captured N canvases, found M regular images". These are raw capture counts, not the deduped/clustered page count produced at stop.

CloakBrowser canvas fetch/intercept emits detailed JSON `log` events while inspecting and saving canvases. Those logs include DOM backing size, CSS box size, viewport visibility, export errors, data URL shape, decoded PNG size, byte size, and simple black/transparent pixel diagnostics; Rust forwards them to the runtime log for troubleshooting pages that export blank or low-quality canvases.

**Deep-capture diagnostics.** The deep-capture path is instrumented so a runtime log alone answers "where is the time going" and "what did the interception actually find", without re-running the capture. Every line is prefixed `cloak deep <kind>:` and is greppable; `_debug_log` carries the routine ones and `_warn_log` (same transport, `warn` level, not gated by `VERBOSE_DOWNLOAD_LOG`) the ones the user must see. The line families are: `drain` — exactly one aggregated line per drain (never per image) with whole-drain wall time, the per-stage time/new-record split (`network`, `page-events`, `canvas-native`, `dom-order`), running totals split canvas/image, and the slowest browser calls; `shape` — page URL plus element/`<img>`/complete-`<img>`/`<canvas>`/`<iframe>` counts, logged on the first drain, at stop, and only when the shape actually changes, so a static paged reader reads as one line instead of one per poll; `stall` — one warning per idle episode once `DEEP_CAPTURE_STALL_SECONDS` pass with no new payload (naming the observed shape), plus one line when captures resume; `call` — a single browser call over `DEEP_CAPTURE_SLOW_CALL_SECONDS`; `start` / `stop` / `settle` / `screenshots` — lifecycle phase timings; `summary` — the stop block, one counter line (payloads, decoded, exact dupes, undecodable, blank-dropped, dom-collapsed, cluster-merged, pages, probable junk) followed by one line per capture source with its raw/page/junk counts. Constraints this must keep satisfying: browser calls are timed through the one `_timed_deep_call` helper (per-label aggregation, so the per-canvas screenshot loop is one table entry); the page shape is counted **inside** the DOM-order walk `COLLECT_DOM_IMAGE_ORDER_JS` already performs and returned alongside it as `{items, shape}`, so diagnostics add no DOM round-trip; and the collector stays observe-only.

## Files and submodules

This package is now headless-only: the legacy PyQt6 "New project" UI (`window.py`,
`downloaders.py`, `import_ops.py`, `save_ops.py`, `stitching.py`, `waifu2x.py`, the
`batch_nodes_window/` node editor, and the UI-level `test_adv_fetch*` tests of that era)
was rewritten in Rust under `src/launcher/new_project/` and archived in `old_or_test/2.X/`.
Only the browser-fetch daemons hosted in-process by the AI backend remain here, together
with the browser-free `test_adv_fetch_cloak_cli.py` unit tests listed below.

- `__init__.py`: import-light package init. It must NOT import any PyQt6/UI module, because the
  AI backend imports `modules.new_project.adv_fetch_cli` and initializes this package first.
- `adv_fetch_cli.py`: Selenium daemon for open-url, candidate fetch, link collection, canvas fetch, and canvas intercept commands.
- `adv_fetch_cloak_cli.py`: CloakBrowser/Playwright daemon with the same Rust-facing command protocol, deep capture mode, and persistent `modules/browser_profiles/cloak_profile` profile.
- `common.py`: shared helpers for URL/pattern handling used by the fetch daemons.
- `test_adv_fetch_cloak_cli.py`: browser-free unit tests for `adv_fetch_cloak_cli.py` — active-tab
  resolution and the deep-capture page-ordering pipeline (`_combine_dom_order`,
  `_append_first_seen_keys`, the site page-index path and its authority gate,
  `_deep_capture_sort_key` tiers, and the stop-time call order around the screenshot pass), plus
  the pure deep-capture diagnostics helpers (`DeepCaptureStallTracker` episode/recovery edges,
  `DeepCapturePageShape` parsing and change signature, `_deep_capture_source_breakdown`,
  `_format_deep_capture_summary`, `_format_deep_call_stats`, `_format_deep_drain_stages`). It
  exposes a `__main__` runner as well, because the project venv has no pytest; run it with
  `PYTHONPATH=<repo> ./venv/bin/python modules/new_project/test_adv_fetch_cloak_cli.py`.

## Contracts and invariants

- `_handle_command` is the single command contract reused by both transports: it takes one command dict and reports exactly one terminal event (plus interim `progress` events) through `self._emit`. `BrowserService` depends on this shape, so it must be preserved.
- Browser commands run inside the always-on AI backend, serialized by `BrowserService`'s lock AND pinned to one dedicated owner thread (`BrowserService._browser_executor`, `_run_on_browser_thread`). The IPC dispatcher runs each request on an arbitrary pool worker, but Playwright's sync API is greenlet-bound to the thread that launched the context, so `_handle_command` and daemon `close` must always run on that single thread. Selenium/Playwright imports must stay lazy so AI-only startup never loads them.
- Version compatibility is reported via the `version` command (`downloader_version`); the legacy `ready` stdout event only matters for the manual `--daemon` fallback.
- Selenium driver calls must remain in the daemon-owned browser context. Browser-tab fallbacks are serialized because WebDriver is not thread-safe; the requests pass may use `max_parallel`.
- CloakBrowser page calls must remain serialized through the helper's page lock and must run on the browser-owner thread; background collection loops must not run concurrent Playwright page operations against the same context.
- CloakBrowser uses Playwright's sync API; browser callbacks and Python background threads (e.g. the link-collect loop `_collect_links_loop`) must not call Playwright methods on their own thread. They must marshal each Playwright call onto the owner thread via `self._run_on_browser_thread(...)` (a passthrough when the daemon runs standalone; overridden by `BrowserService` in-process). Any state the daemon exposes must have a rollback path so a failed browser call does not wedge a "started" flag (see `start_deep_intercept`, which clears deep-capture state on error).
- Progress events should remain monotonic for a fetch run.
- Temporary output folders contain only successfully decoded images, named in page order.
- Auto-review cancellation is cooperative and must preserve already decoded images rather than killing the daemon.
- Auto-review downloads must reject redirects and text/page-like URL suffixes while still accepting extensionless or otherwise unusual URLs when the returned bytes decode as supported image data; misleading HTTP content types must not override byte-level image validation.
- Auto-review group rejection is pre-download and group-scoped: failed candidates are counted before the Rust review step so unproductive URL families stop being attempted.
- **Active-tab resolution is one shared, memoryless mechanism used by every download mode** (`fetch`, `fetch_auto`, `link collect`, `canvas`, `deep intercept`), via `_resolve_active_page` / `_active_page_url`. It picks the tab the user currently has in front and **must not** bind to a remembered/tracked page (`self._page`), the first/most-recently-opened tab, or the initial `open_url` URL. Do not reintroduce ranking by URL pattern or canvas count — every mode targets the same active tab. Mechanism: an observe-only monitor (`ACTIVE_MONITOR_JS`, installed once via `context.add_init_script` in `_ensure_browser` plus a one-time seed of tabs already open at launch) timestamps each tab's last foreground transition (`visibilitychange`→visible / `focus` / `pointerdown` / `keydown`) into `window.__mfActiveMonitor`; the resolver reads it (`ACTIVE_MONITOR_READ_JS`) across live real-URL tabs and picks the newest timestamp (tie-break: current `visibilityState==='visible'`). This is required because instantaneous `document.hasFocus()`/`visibilityState` both read false once the Studio window takes focus and the Chromium window is occluded — recording the last *transition* survives that. The monitor is strictly observe-only (passive listeners + one `window` object, no prototype patching) so CloakBrowser stealth is untouched. Degenerate cases: exactly one live real-URL tab is used as-is; none present raises the standard "Сначала откройте страницу главы" error.
- Every use of the resolved page must tolerate the tab closing between resolution and use: `_reload_capture_page` (deep capture) re-resolves the active tab and retries on `TargetClosedError` (detected via `_is_target_closed`, since Playwright does not re-export it from `sync_api`). Cloak deep capture must reload the active page after installing init hooks; output classification must remain byte-based and feed the same Rust auto-review contract instead of bypassing the review window. Only that one tab is reloaded.
- Cloak deep capture auto-review items use one synthetic `deep-capture://capture/page/*.png` URL family so captures from network, blob, data, and canvas sources stay in one review group; source URLs are diagnostic metadata, not grouping keys. Finalization is a content pipeline: blank (near-uniform black/white) frames are dropped globally so off-screen unrendered canvases never become pages; remaining frames are collapsed to the best frame per element (keyed by stable WeakMap id, then `dom_order`); records are clustered by perceptual hash so one page captured through several layers is one page; the highest-fidelity representative wins per cluster; pages are ordered by the tiers in `_deep_capture_sort_key` — the site's own published page index when it is authoritative, then position in combined page document order, then per-snapshot DOM-walk order, on-page geometry, URL-embedded page numbers, and finally capture order; size-outlier pages are flagged `probable_junk` and the review window opens with them unchecked.
- **Site page index (opt-in, highest ordering tier, gated).** `COLLECT_DOM_IMAGE_ORDER_JS` reads, for every emitted image URL / canvas key, the first of `data-page` / `data-index` / `data-idx` / `aria-posinset` (`DOM_PAGE_INDEX_ATTRIBUTES`) carried by the element itself or its closest ancestor, accepting only a plain non-negative integer. This is what makes a reader that renders some pages as `<img>` and others as `<canvas>` come out as one sequence: the containers usually all exist from first paint, so a single DOM read yields the complete mapping without scrolling. A site publishing no such attribute produces empty maps and `authoritative=False`, so ordering is bit-for-bit what it was before this tier existed. The attribute walk is observe-only (attribute reads, bounded hops, memoized per ancestor); it crosses shadow boundaries via the host but **cannot climb out of an iframe** — an iframe document's root node has no host, so elements inside a frame simply resolve no index.
- **The index tier is only as trustworthy as its gate** (`_site_page_index_authority`, decided in `_finalize_dom_capture_order`). Every ratio counts **DOM elements, not keys**: one `<img>` emits up to four URL variants sharing one payload `order` slot while one `<canvas>` emits a single key, so key-counted ratios are systematically biased towards "the images are indexed". The index is accepted only when at least two elements publish one, every populated key space (image *and* canvas) contains at least one indexed element, indexed elements are a strict majority (full coverage is unreachable — site chrome images come through the same DOM walk), the values discriminate (≥2 distinct, distinct values covering ≥ half the indexed elements, so one shared wrapper `data-index` is refused), and the values are already non-decreasing in document order for ≥4/5 of the indexed elements (a thumbnail strip or ad rail whose numbering restarts is refused). Once accepted the index is **gap-filled**: an element publishing no index inherits its nearest indexed predecessor's slot, so a partially tagged document never splits into an indexed and an unindexed sort tier. `_deep_capture_sort_key` puts combined document order immediately after the primary value, so every tie inside a tier degrades to document order, never to network arrival order.
- The cumulative deep-capture DOM order (`_accumulate_deep_dom_order`) is refreshed on every drain by plain first-seen append (`_append_first_seen_keys`): each poll's window of image-URL/canvas-WeakMap-id keys is appended in encounter order, along with any page index and the owning DOM element seen for a key (first reading wins). Anchor-based insertion must not be used for accumulation — consecutive polls often catch non-overlapping windows during a fast scroll, and inserting a non-overlapping group relative to absent anchors scrambles the sequence into small correctly-ordered fragments.
- At stop, `_combine_dom_order` **merges** the accumulated first-seen order into the live stop-time DOM order: every key that has left the DOM is anchored to the next key that follows it in first-seen order and is still present at stop, and is emitted immediately before that anchor. Both inputs must already be de-duplicated. Invariants: keys present at stop keep their stop-time relative order unchanged (that order is the reliable one, since fast scrolling can scramble pure first-seen accumulation); vanished keys stay interleaved between their first-seen neighbours; nothing vanished degenerates to exactly `stop_keys`; nothing present degenerates to exactly the first-seen order. Vanished keys must **not** be concatenated as a leading block — on a reader where `<img>` pages persist in the DOM but `<canvas>` pages are torn down when scrolled away, a leading block splits one chapter into two internally-ordered halves.
- `stop_deep_intercept` must accumulate the DOM order **on both sides of the canvas screenshot pass**: `ElementHandle.screenshot()` scrolls each element into view, which is exactly what recycles elements on a virtual-scroll reader, so the pre-screenshot reading is the only surviving evidence for the keys that pass tears down. Do not reorder these calls.
- Browser sessions are cached and reused across commands, but `_ensure_browser` must verify the cached session is still live and relaunch when it is not: any failure probing the Selenium driver (closed window, dead chromedriver, invalid session) drops it, and a CloakBrowser context with no live page (the user closed the browser) is torn down and recreated. A command like `open_url` must always end up with a live browser instead of erroring on a stale one.
- Errors returned to Rust must distinguish user-facing messages from technical log messages.

## Editing map

- To change advanced browser image extraction, edit `adv_fetch_cli.py`.
- To change wildcard/prefix matching shared by download flows, edit `common.py`.
- The legacy Python "New project" UI now lives in Rust (`src/launcher/new_project/`); the old PyQt6 sources are archived under `old_or_test/2.X/modules/new_project/`.
